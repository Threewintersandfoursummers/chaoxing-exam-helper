## 二、真机才发现的三个硬事实

### 1. 选项行不可点击、不可勾选，选中态完全不可见

整棵 UI 树里只有 **4 个 `clickable="true"`**：根容器、顶栏、返回按钮、「下一题」。

选项行一个都不是。而且是 `checkable="true"` 的数量为 **0**。

更关键的实验：点完 B 选项后重新 dump，**UI 树字节数一模一样（21393 → 21393），新增节点 0，消失节点 0**。

**结论：程序永远无法从无障碍层确认自己点中了没有。**

这条直接决定了三件事：

- 不能用「检测到已选中」来决定跳过，只能用自己的 `state.done` 记账
- 不能盲点第二次做重试 —— 多选题盲点第二次会把已选的**取消掉**，比没点更糟
- 终局不能声称「全部答完」，只能说「点过了」

代码里已经按这个前提改了：先探测界面暴不暴露选中态（`selectionObservable`），不暴露就直接清空待验证队列，不制造虚假告警。

### 2. 选项标签是「单独一个字母」，后面不带任何标点

真机结构：

```
TextView  "A"            ← 标签独立节点，没有「、」也没有「.」
TextView  "中国共产党"     ← 正文是它右边的兄弟节点
```

原来只认 `A、xxx` / `A.xxx` 这种整串写法，结果 **4 个选项一个都认不出来**，整题退化成「简答题」。

由于题号 `1.`、分值 `（2.0分）`、题干三者 y 坐标几乎重合（都是 y=593），
`（2.0分）` 还会被拼进题干 —— 拿去和题库比对永远命不中。

这三条都已修，并写了基于真实 dump 的回归用例（`test/uia.test.mjs` 第 8 节）。

### 3. 选项文字被两端对齐拉开空格

`text-align: justify` 会把短选项拉成「从 严」「治 理」。

不处理的话，按选项原文匹配、题库比对全部失效。现在只压「两个汉字之间」的空格，英文单词之间的空格保留。

## 四、还没验证的（缺一样东西）

**LLM 解题这一段没跑过真实接口。** 因为 `config.json` 里还是占位符 key。

抽题、落点、点击、翻页都是真机验证的；只有「把题发给模型、拿回答案」这一段还是模拟的。

这一段的风险不在逻辑（`smoke` 22 项覆盖了投票、归一等），而在**真实模型的输出格式**：真实返回可能带寒暄、markdown 围栏、或者干脆拒绝回答。解析器有六级降级兜底，但没用真 key 打过。

填上 key 后跑这一条就能补齐：

```
node src/single.mjs dry
```

它会完整解一遍并打印「本来要点哪里」，但**一次点击都不发**。

## 五、给考场的提醒

现在能确认的是「程序看得懂、点得准」。剩下两个风险是这套方案无法消除的：

1. **摄像头抓拍 + 人脸活体** —— 人不在场必挂，无软件解
2. **点击虽然生效，但程序不知道自己点中没有** —— 万一某次点击落空，它不会补，也不会报错。所以**交卷前必须自己滚一遍答题卡**

第 2 点没法靠代码解决（界面不暴露选中态），但可以用流程兜住：程序只负责答，你在提交前手工核对一遍答题卡有没有空格。这一步别省。
