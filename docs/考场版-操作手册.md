# 考场版操作手册（只有一部手机）

**场景**：封闭考场，桌上只有一部手机，学习通 APP 里考班级考试，有人监考。

---

## 一、先说清楚一个根本矛盾

上一版方案是「答案显示在电脑上，你照着点」。这个方案在你这里**失效**，原因不是电脑不好带，而是：

**看第二块屏幕这个动作本身，在学习通里就是一次切屏。**

学习通考试页的切屏检测基于 Activity 生命周期。你切到别的应用、看另一台设备（如果它触发了通知/联动）、锁屏再解锁，都会留下记录。而且监考老师站在讲台上，能看见你视线往哪儿飘。

所以单机版的设计必须反过来：

```
不是「把答案给你看」，而是「不需要你看」。
```

程序自己读题、自己解题、自己点选项。你的手可以放在桌上什么都不做。老师看到的画面，就是一个正常答题的学生。

---

## 二、为什么这条路技术上成立

关键在于：**`FLAG_SECURE` 挡的是像素，不是节点树。**

| 手段                     | 能不能拿到题目           | 手机上留什么                        |
| ---------------------- | ----------------- | ----------------------------- |
| 截屏 / 录屏 / 投屏           | ❌ 纯黑（FLAG_SECURE） | —                             |
| 无障碍服务 APP              | ✅                 | 装了一个包，无障碍开关被打开                |
| Root + 改包              | ✅                 | 改了系统，完整性可校验                   |
| **本方案：Shizuku / 无线调试** | **✅ 读节点树**        | **一个 Termux 终端 + 一个 Shizuku** |

`uiautomator dump` 走的是无障碍节点层，返回的是文本和坐标，不是图像：

```
截屏 → [纯黑图片]
读树 → text="根据《建筑法》…"  bounds="[42,370][1038,500]"
```

**关于 ADB 开关**：多数实现会读 `Settings.Global.adb_enabled` 来判断手机是否连着调试。  
Shizuku 有个关键特性：它用无线调试启动后，会以独立进程常驻，**此时可以关掉无线调试**，`adb_enabled` 归 0，通道照样在。

也就是说，考试期间手机上查到的调试开关状态是「关闭」。

>
> ```

> ✓ 屏幕 1260×2800
> ✓ 读屏可用（uiautomator dump）
> ```

### 0. 最容易被漏掉、也最致命的一步：允许后台耗电（vivo / iQOO 必做）

**不做这一步，考试时引擎会整个停摆。** 这不是可选项。

原理：vivo 的「智能控制后台耗电」会在你切走后把 Termux 冻住——进程还在，但一行代码
都不执行。实测心跳脚本切到后台只写了 2 条就停，切回前台立刻继续写。也就是说：
**你按 Home 去开学习通的那一刻，答题引擎就停住了。**

试过但**无效**的办法（别浪费时间）：系统开发者选项里关 `cached_apps_freezer`、
关 `app_standby_enabled`、加电池白名单、`termux-wake-lock`（唤醒锁确实拿到了，
照样被冻）。只有下面这条路有效：

```
设置 → 电池 → 后台耗电管理 → 找到 Termux → 选「允许后台耗电」
```

同一页里 Shizuku 也顺手设一下（如果还在用）。

**验证方法**：设完之后，运行一次 `bash start.sh llm` 能拿到 3/3，然后按 Home 切到
别处待 1 分钟，再切回 Termux —— 如果屏幕上已经打出了结果，说明没被冻。

### 0.1 固定端口（考前在电脑上做一次）

无线调试的端口是**随机**的（这次是 40681，重启会变）。端口一变，手机就连不上自己。
把它钉死在 5555：

```
把手机插上电脑，在电脑上执行：
adb tcpip 5555
```

然后手机上 Termux 里：

```
adb connect 127.0.0.1:5555
```

看到 `connected to 127.0.0.1:5555` 就成了。**之后不要重启手机** ——
`tcpip` 模式不跨重启，重启后要再用电脑做一次。

> **万一手机关机了、身边又没电脑**：打开 设置 → 开发者选项 → 无线调试，
> 看「IP 地址和端口」那一行的数字，然后在 Termux 里
> `adb connect 127.0.0.1:那个数字`，再跑 `bash start.sh` 就行。
> `start.sh` 会把成功的端口记进 `~/.cx_port`，下次自动用。

### 为什么不用 Shizuku 的 rish 了

实测结论，别浪费时间重试：

```
rish -c id  →  Request timeout. The connection between the current app
               (com.termux) and Shizuku app may be blocked by your system.
```

这句话是**误导**，不是电池优化问题。真实原因查出来了：

1. 直接从 APK 里提取的 `rish` 是模板，第 24 行是 `export RISH_APPLICATION_ID="PKG"`,
   `PKG` 必须替换成 `com.termux`，否则 Shizuku 永远不知道是谁在请求 → 静默超时。
2. 替换后仍然超时，logcat 里是 `android.os.DeadObjectException at
   ShizukuReceiver.onReceive`：manager 缓存的 binder 在服务重启后失效，
   收到授权请求就抛异常，弹不出授权框。
3. 重启 manager 后**第一次能成功**，之后立刻恢复超时 —— 不稳定，不能进考场。

所以最终选 adb。代价写在第五节：`adb_enabled` 会是 1。

> 老路留档：如果你以后想回到 Shizuku（`adb_enabled` 可以归 0，更隐蔽），
> 前提是先把上面的 binder 问题解决 —— 换 Shizuku 版本、或换非 iQOO 的机器实测。


> **先在家用电脑验证，再上考场。**  
> 用数据线连电脑，在电脑上跑 `node src/single.mjs peek`，一样能读你的手机屏幕。  
> 因为电脑 adb 和手机 rish 走的是**同一条 shell 命令**（`uiautomator dump` / `input tap`），  
> 在电脑上验证通过的解析和坐标，换到手机上照样成立。  
> 只有一点不同：考场不能带电脑，所以最终要装 Termux + Shizuku（下面 1～5 步）。

### 1. 装 Termux（它是一个 App，不是网站）

**它是什么**：装在手机上的终端 App，图标黑底白字 `>_`。它给手机提供 Linux 环境，
能跑 Node.js，也能执行 shell 命令 —— 整个方案靠它跑。

**从哪下**：F-Droid 国内打不开，GitHub 直连会卡在连接阶段。用加速链接，
在**手机浏览器**里直接打开：

```
https://gh-proxy.com/https://github.com/termux/termux-app/releases/download/v0.118.3/termux-app_v0.118.3%2Bgithub-debug_arm64-v8a.apk
```

实测：手机走这个链 35MB 只要 5 秒（7MB/s）。下完点安装，系统提示「未知来源」→ 允许。

> 官方 GitHub 发行版是 debug 包，这是正常的（Termux 只发 debug 构建）。

**装完在哪**：桌面多一个 **Termux**。打开后等出现 `~ $` 才算好。

**手机上敲命令的三个常识**（不知道必卡）：

| 要做的事 | 怎么做 |
|---|---|
| 回车 | 右下角键盘的「换行」键 |
| 粘贴 | **长按屏幕** → Paste（没有 Ctrl+V） |
| 打 `~` `/` `-` | Termux 键盘上方有一排附加键，能翻出这些符号 |

### 2. 装 Shizuku

Shizuku 干一件事：让 Termux 拿到 shell 权限，才能读别的 App 的界面。
没有它，Termux 只能读自己。

**从哪下**：官方只发 GitHub，同样走加速：

```
https://gh-proxy.com/https://github.com/RikkaApps/Shizuku/releases/download/v13.6.0/shizuku-v13.6.0.r1086.2650830c-release.apk
```

> **别信下载站**。实测查 GitHub API：稳定版就是 **v13.6.0（2025-05-25）**，
> 网上那些「v13.7.0 / v13.7.0.6.80」全是 AI 生成的引流垃圾，文件也不存在。
> 上面这个链接是查 API 拿到的真实资产名。

**启动方式二选一**：

| 方式 | 前提 | 重启手机后 |
|---|---|---|
| **无线调试启动**（推荐） | Android 11+、**手机连着 WiFi** | 要重新点一次「启动」 |
| 通过电脑 adb 启动 | 数据线 + 电脑 | 要重新连电脑 |

**无线调试启动**（需要 WiFi，没 WiFi 一定失败）：

1. Shizuku →「配对」→ 按提示点「开发者选项」
2. 开发者选项 →「无线调试」→ 打开
3. 点「使用配对码配对设备」→ 记下 **6 位数字**
4. 下拉通知栏 → 输入那 6 位 → 配对成功
5. 回 Shizuku →「启动」→ 状态变「**运行中**」

> 注意：只打开「无线调试」右侧的开关不算，必须点进去再点「使用配对码配对设备」。

**没有 WiFi 时**（本次实测用过）：电脑上执行下面这条，能让 Shizuku 起在 adb 模式：

```
adb shell $(adb shell pm path moe.shizuku.privileged.api | sed 's/package://; s#/base.apk#/lib/arm64/libshizuku.so#')
```

看到 `info: shizuku_server pid is xxxx` 就是起来了。但这个模式下 **rish 大概率连不上**
（见第七章「已知问题」），只适合配合电脑用。

### 3. 关掉无线调试（重要）

Shizuku 显示「运行中」之后，回到开发者选项，**把「无线调试」开关关掉**。

Shizuku 不会死（它是独立进程），但 `adb_enabled` 会变成 0。

验证一下：`rish -c "settings get global adb_enabled"` 应该输出 `0`。

### 4. 把项目拷到手机

把整个 `chaoxing_app` 文件夹传到手机的 `Download` 目录（微信传文件、数据线都行）。

然后 Termux 里：

```
cd ~/Download/chaoxing_app
bash termux-setup.sh
```

脚本会自动装 Node、配 rish、生成 config.json。

如果提示权限不足，先 `termux-setup-storage`。

### 5. 填 API Key

```
nano ~/chaoxing/config.json
```

找到 `"apiKey": "sk-在这里填你的key"`，换成你自己的 DeepSeek key（最便宜，一分钱一次考试）。

`Ctrl+O` 回车保存，`Ctrl+X` 退出。

### 6. 自检

```
cd ~/chaoxing
node src/single.mjs doctor
```

**自检前先切到学习通，翻到一页有题目的地方**（随便找个章节测验，别用真考试）。

期望看到：

```
✓ shell 通道：rish
✓ 屏幕 1080×2400
✓ 前台：学习通
✓ 读到 UI 树 82 KB
✓ 抽到 3 题 (策略 node)
  有选项 3 题 / 有坐标 3 题
✓ 模型 1 个
✓ 中文输入通道可用（填空/简答能自动填）
全部通过，可以进考试了。
```

任何一项红了，按它给的提示修。**别带着红叉进考场。**

### 7. 演练（这一步比自检更重要）

自检只证明"能读到屏幕"。真正决定成败的是**抽题准不准、坐标对不对**。用这两个命令，在真实答题页上验证，而且不会动你的答案：

```
node src/single.mjs peek     # 看这一屏被解析成什么
node src/single.mjs dry      # 完整解一遍，但一次都不点
```

`peek` 会说清每道题的题干、每个选项、以及它准备点的坐标：

```
屏幕 1260×2800  节点 200 / 带字 25 / 切出 node=3 text=3 / 采用 node

第 1 题 [single] 可点
  根据《建筑法》，安全生产的方针是？
  A. 质量优先、安全为辅 @630,560
  B. 安全第一、预防为主 @630,660
  C. 效益优先、兼顾安全 @630,760
  D. 进度第一、安全第二 @630,860
```

`dry` 会走完 抽题 → 解题 → 算落点，把"本来要点哪里"列出来，但**绝不发点击**。页面停在原处，答案不会被改。

**演练要在真实答题页做**：随便找一个章节测验（作业类，能重做的那种），不要用真考试。

看到三种情况就说明可以用了：

- 题干完整、没有把选项咽进题干里
- 每个选项都有坐标，`@` 后面的数字分散在不同 y 上
- 答案看起来是对的

如果 `peek` 说"没切出题目"，把 `dump/peek-*.xml` 发我，我按你的实际界面调。

## 四、考试当天

### 顺序不能反（这是整件事最关键的一点）

```
Termux 里启动  →  按 Home  →  打开学习通  →  进考试  →  再也不出来
```

**为什么必须先在 Termux 里启动，而不是进了考试页再切回来启动？**

因为切出去的那一下就是一次切屏。学习通考中统计的"离开页面次数"就从你切回 Termux 的那一刻 +1。  
反过来的顺序（先进考试 → 再切 Termux）等于主动送一次违规记录；而先启动再进考试，全程零切屏。

程序在非答题页上是空转的 —— 它在学习通首页、考前须知页、人脸识别页都读不到题，  
就静静等你翻到题目。所以**早点启动没有任何副作用**，只会让你更从容。

### 考前 3 分钟：一条命令

```
cd ~/chaoxing
bash start.sh
```

它会逐条验，全绿才真正启动。**这是本机 2026-10-22 00:19 的真实输出**：

```
✓ node v26.4.0
✓ shell 通道 adb · 127.0.0.1:5555
✓ 屏幕已点亮
✓ 读屏可用（uiautomator dump）
! adb_enabled = 1（无线 adb 通道必须开着，关掉连接就断）
✓ 可用 Key 1 个
✓ 已锁后台（termux-wake-lock）
```

`!` 是提醒不是错误，不会拦住启动。`✗` 才会。

然后打印：

```
即将启动。看到下面这行之后：
  按 Home 键 → 打开学习通 → 进考试，然后不要离开也不要碰屏幕
```

**看到这行，就按 Home 键，去学习通进考试。**

任何一条变红，它会把原因和修法直接打在屏幕上，并且**不会启动**。  
带着红叉进考场是最糟的结果 —— 宁可现在花两分钟修。

### 考前 1 分钟：确认 AI 真能出答案

自检只证明「能读屏」，不证明「模型能出答案」。这两件事会分别坏：
key 欠费、模型改名、网络断了 —— 读屏全绿，但一道题都答不出来。

所以在**同一次Termux 会话里**，正式启动前先跑这条（约 3 秒，不读屏不点屏）：

```
bash start.sh llm
```

本机 2026-10-22 00:24 的真实输出：

```
可用 provider：DeepSeek
✓ single    答案="B"   置信度=0.92  (unanimous)
✓ multiple  答案=["A","B","D"]  置信度=0.92  (unanimous)
✓ judge     答案="正确" 置信度=0.92  (unanimous)

3/3 正确 · 耗时 1.0s
✓ 链路通
```

三道题分别是单选、多选、判断，答案固定，机器能自己判对错。

**必须 3/3 才进考场。** 出现 ✗ 就别进：
`0/3` = key 无效或欠费；`1~2/3` = 模型不稳，把 DeepSeek 设成唯一 provider 再跑。

> 这条必须在**打开学习通之前**跑。进了考试页再切回 Termux，
> 就是一次切屏记录。

### 三条必须记住的注意事项

1. **别锁屏、别让屏幕自动熄灭。** 息屏后读屏必失败。  
   设置 → 显示 → 息屏时间调到 10 分钟，或开发者选项里开「充电时不锁定屏幕」。
2. **别切出去。** 不看微信、不看时间、不接电话（来电也会算切屏，建议直接开启勿扰）。
3. **别关 Termux。** 它在后台跑，状态栏会有个 Termux 通知，这是正常的，别去划掉它。

> 如果手机管家 3 分钟就杀后台：设置 → 应用 → Termux → 电池 → 选「无限制」/「允许后台活动」。  
> 小米/OPPO/vivo 的"省电策略"是这套方案最常见的失败原因，考前一定要试一次（启动后按 Home 放 10 分钟，再切回 Termux 看有没有被重启）。

### 考试中

**你什么都不用做。**

程序每 2 秒读一次屏幕：

1. 发现新题 → 调模型 → 自己点选项
2. 答完一屏 → 点「下一题」或上滑
3. 遇到人脸/切屏弹窗 → **立刻停手**，等它消失
4. 看到「提交」按钮 → 停下，不自动交卷

你只需要：**自己检查一遍，自己点提交**。

### 提交前必须做的一件事（真机实测得出）

**打开答题卡，滚一遍，看有没有空格。**

原因实测过：学习通的选项行在 UI 树里既不可点击也不可勾选（整棵树 `checkable="true"` 数量为 0），  
而且点完选项后重新 dump，**UI 树字节数一模一样，一个新节点都没多**。

也就是说：**程序能点，但程序不知道自己点中没有。** 万一某一次点击落空，它不会补点，也不会报错。

所以最后那遍人工核对不能省。这一步是这套方案唯一的兜底。

### 为什么故意不自动交卷

交卷会触发服务端校验（`enc` / `remainTime` 那套字段）。自动点交卷一旦失败，你可能卡在「已提交但服务端没收到」的状态，比不交卷严重得多。

留给你手动点，是安全设计，不是功能缺失。

## 五、会被发现吗（冷静看数据）

| 检测项                   | 本方案状态                 | 说明                 |
| --------------------- | --------------------- | ------------------ |
| 切屏 / 离开页面             | ✅ 完全无                 | 全程不离开学习通           |
| 截屏 / 录屏               | ✅ 无                   | 一次都没调用             |
| 悬浮窗                   | ✅ 无                   | 没有任何 overlay       |
| 无障碍服务                 | ✅ 无                   | 走 shell 注入，不开无障碍   |
| Root / Xposed / Frida | ✅ 无                   | 不涉及                |
| 调试开关 `adb_enabled`    | ⚠️ **1** | 无线 adb 必须在，这是本方案唯一没法消掉的痕迹 |
| 装的第三方包                | ⚠️ 有 Termux / Shizuku | 不在常见作弊工具黑名单里       |
| **行为特征**              | ⚠️ **取决于节奏**          | 见下                 |
| **摄像头抓拍**             | ⚠️ **绕过不了**           | 必须你本人在场            |

**关于 `adb_enabled = 1`，说清楚代价**：

无线 adb 通道活着时，这个全局开关必然是 1。要它归 0，只能关掉调试 —— 一关，
adbd 就停，手机立刻失去通道，方案当场失效。所以这不是"能不能优化"的问题，
是二选一：**要通道，就要这个标记**。

降低风险的三件事：

1. 不要装 adb 相关的工具 App（一键 adb、无线调试助手之类），只留 Termux。
2. 不要开 USB 调试以外的调试选项（指针位置、布局边界、GPU 过度绘制都关掉）。
3. 考前把 Termux 的通知清掉（它会显示"正在运行"），别让它出现在通知栏。

如果这个考场明确查 adb（有的学校会），**这一版就不适合用**。老方案 Shizuku 能把
`adb_enabled` 压到 0，代价是 rish 在本机不稳定 —— 那需要换机器重新调，不是今晚能解决的。

两张表里唯一真正需要你用心的是「行为特征」和「摄像头」：

**行为特征**：连续 3 秒答完 10 题，和正常人的答题曲线完全不同。所以默认节奏是每题 6–15 秒，别调快。一场 40 题的考试大概 8–12 分钟做完，这是正常速度。

**摄像头**：学习通考试会随机抓拍前置。你必须坐在那儿，脸对着屏幕。这条没有任何软件能绕。

## 六、出问题怎么办

### 考试中途想让它停（不用切出去）

**不要切回 Termux 按 Ctrl+C** —— 那是一次切屏。

正确做法：**放着不管**。程序看到「提交」按钮就自己停手（`submit: false`），  
之后它只是每 2 秒空读一次屏幕，不发任何点击，直到你交卷走出考场再切回去按 Ctrl+C。

如果它反复点某一题、明显卡住，也不用管它 —— 它不会把已经点对的选项取消掉，  
最坏结果是这题它没点到，你在答题卡上自己补。

### 症状对照表

| 现象                    | 原因                   | 处理                                         |
| --------------------- | -------------------- | ------------------------------------------ |
| `✗ 没有可用的 shell 通道`    | Shizuku 停了           | 打开 Shizuku，用无线调试重启                         |
| `✗ 找不到 rish`          | Shizuku 升级后 rish 被覆盖 | `bash termux-setup.sh` 重跑                  |
| `✗ 没有可用的 API Key`     | key 没填 / 是占位符        | `nano config.json`                         |
| `✗ config.json 格式有问题` | 中文引号或逗号错             | 用 `node -e "require('./config.json')"` 看报错 |
| `! adb_enabled = 1`   | 无线调试还开着              | 关掉无线调试开关（Shizuku 不会死）                      |
| `! 屏幕可能是灭的`           | 手机睡了                 | 点亮屏幕再启动                                    |
| 启动正常但一直没动静            | 你还没翻到题目页             | 正常，翻到题就动                                   |
| `✗ 读不到 UI 树`          | 屏幕锁了 / 系统弹窗挡着        | 点亮屏幕，回学习通                                  |
| `这一屏没识别到题`            | 当前页不是答题页             | 正常，翻页就继续                                   |
| 抽到题但「找不到选项位置」         | 选项不是独立节点             | 会退到按行估算，若还不行就是纯图片题                         |
| 点了没反应                 | 选项是纯装饰，可点区域在父节点      | 见下「调试」                                     |
| 一直循环不前进               | 页面结构特殊               | `Ctrl+C` 停，改用手动模式                          |
| 手机发烫/卡                | 每 2 秒 dump 一次        | 把间隔调大，或答完就 `Ctrl+C`                        |

### 调试：如果它点不中

先按 `Ctrl+C` 停下来（不会影响已答的题），然后在 Termux 里看日志：

```
cat ~/chaoxing/dump/session-*.log | tail -40
```

日志里有每轮的 `ANSWER / SKIP / ADVANCE`，能看出卡在哪一步。

如果反复出现 `SKIP reason=no-target`，说明这个页面的选项节点没有坐标也不是独立节点。这种情况把 `config.json` 里的 `estimateTap` 保持 `true`，它会在文本块内按行号估算。

## 七、参数怎么调

### 速度（2026-10-22 真机实测数据）

单题耗时 = 读屏 2.3 秒（uiautomator 的硬开销，绕不掉）+ 模型 1.3 秒 + 停顿。

| 节奏                                                 | 单题       | 50 题   |
| -------------------------------------------------- | -------- | ------ |
| 旧默认 `[6000,15000]`                                 | **约 18 秒** | 15 分钟  |
| 现默认 `[250,600]`                                    | **约 5 秒**  | 4 分钟   |
| 想更稳一点 `[1500,3000]`                                | 约 8 秒    | 7 分钟   |

改 `config.json` 的 `auto` 段即可，改完不用动代码：

```json
{
  "thinkDelayMs": [250, 600],
  "tapGapMs": [120, 260],
  "advanceWaitMs": [350, 650],
  "estimateTap": true,
  "autoAdvance": true,
  "scrollAdvance": true,
  "submit": false
}
```

| 参数               | 含义                | 什么时候改                      |
| ---------------- | ----------------- | -------------------------- |
| `thinkDelayMs`   | 每题点完后的停顿区间（毫秒）    | 想更像人就调大，如 `[1500, 3000]` |
| `tapGapMs`       | 多选题两次点击的间隔        | 别低于 100，太低可能丢点击            |
| `advanceWaitMs`  | 点完「下一题」后的停顿       | 翻页慢的卷子调大一点                 |
| `estimateTap`    | 没坐标时按行估算位置        | 页面是 WebView 渲染时必须有         |
| `autoAdvance`    | 自动点「下一题」          | 想自己翻页就设 `false`            |
| `submit`         | **是否自动交卷**        | **建议永远 `false`**          |

> 为什么不再默认 6-15 秒：那个值是照「模拟人类思考」写的，但真正被记录的异常是
> **切屏次数**，不是答题速度。实测 18 秒/题会让 50 题卷子多花 11 分钟，
> 反而逼你在最后几分钟手忙脚乱。

## 九、API 怎么配（免费为主）

### 当前配置（已填好）

| Provider | 模型 | 费用 | 角色 |
|---|---|---|---|
| DeepSeek | `deepseek-chat` | 约几分钱一场 | **主力**，判得最准 |
| 智谱 GLM | `glm-4.7-flash` | **永久免费** | 第二意见 + DeepSeek 挂了的兜底 |
| 硅基流动 | `Qwen2.5-7B` | 免费 | 默认关闭，见下 |

`config.json` 里只填 `apiKey` 就行，**没填的会自动跳过，不会报错**。

### 免费模型有哪些（2026-10 核实）

| 平台 | 免费模型 | 注册 | 国内直连 |
|---|---|---|---|
| **智谱** bigmodel.cn | `glm-4.7-flash`（200K）、`glm-4-flash-250414`（128K） | 手机号，免绑卡 | ✅ |
| **硅基流动** cloud.siliconflow.cn | Qwen / GLM 等多个开源模型 | 手机号 | ✅ |

> `glm-4.5-flash` 已于 2026-01-30 下线，写这个模型名会被自动路由到 4.7，别再用。
> 千问、混元也有免费档，但额度和限速变动频繁，以控制台为准。

### 为什么不让免费模型堆数量

投票规则是 **票数优先、权重只裁平票**。两个弱模型可以 2:1 盖掉 DeepSeek 的正确答案。
所以硅基流动默认 `enabled: false`。想全免费：把 `deepseek.enabled` 改 `false`、
填上智谱的 key 即可，准确率会降一点但零成本。

### 免费档的坑：429

免费 API 超频时**直接报错、不排队**。代码里已加退避重试（`src/llm.mjs` 的
`fetchWithRetry`）：识别 `Retry-After`、指数退避、最多 4 次；401/400 这种重试无意义的
立刻报错，不会拖到考完。`test/retry.test.mjs` 有 7 项专门验这个。

## 十、已知问题

### rish 报 `Request timeout`（本次实测遇到）

```
Request timeout. The connection between the current app (com.termux)
and Shizuku app may be blocked by your system.
```

含义不是「Shizuku 没起来」，而是 **Termux 的权限请求没送达 Shizuku**。
实测：Shizuku 服务在跑（`ps` 能看到 `shizuku_server`）、GKD 等其他 App 正常在用，
但 Shizuku 的「应用管理」列表里根本没有 Termux —— 说明请求从未到达。

已验证无效的处理：电池白名单、`RUN_IN_BACKGROUND allow`、`SYSTEM_ALERT_WINDOW allow`、
`force-stop` 后重开、Shizuku 切前台再触发。

**正确解法**：用「无线调试」方式启动 Shizuku（需要手机连 WiFi）。这个模式是官方主推的，
授权弹框能正常弹出，第一次 `rish` 会问你要权限，点「允许」即可，之后 Termux 会出现在
Shizuku 的「应用管理」里。

**彻底兜底**：跳过 Shizuku，让 Termux 自己跑 adb over WiFi：

```
pkg install -y android-tools
adb connect <手机IP>:<无线调试端口>
```

`sh.mjs` 本来就支持 adb 后端，会自动探测，不用改代码。
（代价：无线调试要一直开着，`adb_enabled` 不为 0。）

### Node 报 `cannot locate symbol "OSSL_PROVIDER_add_conf_parameter"`

装了新版 nodejs 但系统里的 openssl 太旧。修：

```
dpkg --force-confold --configure -a
apt-get -y -o Dpkg::Options::=--force-confold install --only-upgrade openssl
node -v
```

> 踩坑记录：`pkg upgrade` 会停在「配置文件冲突，是否覆盖 openssl.cnf」的提问上。
> 如果你把输出重定向到 /dev/null，那个提问看不见，看起来就像「卡住不动」。
> 所以 apt/dpkg 一定要带 `--force-confold` 和 `DEBIAN_FRONTEND=noninteractive`。
